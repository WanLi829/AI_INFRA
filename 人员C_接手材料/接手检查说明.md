## 4. 已确认的运行限制

依据固定版本 Kairos 的 [run.py](https://github.com/MaxizYB/Kairos/blob/7971fa40323f16e8e4ce8f12dfd5db9755a98cf1/kairos/run.py)：

- 当前发布要求特定 Qwen3-8B 布局、固定权重版本及 HF snapshot 路径，并核验模型文件。不能只替换 --model 就改用 4B。
- Replay 固定读取 data/workload/trace.json、visible_messages.json，并校验 visible_protocol.json；CLI 没有 --trace 或 --workload 参数。
- CPU helper 的缓存上限 8.0 GB、初始值 4 GB 目前写在启动代码里，没有用户级容量参数。
- 当前入口要求 Linux 相关能力、空闲独占 GPU、启动前至少 40 GiB 可用主机内存；使用 18765–18768 端口。
- engine/helper CPU 亲和集合不得重叠，默认编号不能直接假定适用于你们的服务器。

因此，4B、新数据集、可调 CPU 缓存属于需要与实现小组协调的适配项。当前先以原版固定模型和归档负载复跑作为接手检查更稳妥，之后再接入新实验配置。

## 8. 共享卡 wrapper 审查

已阅读 [run_relaxed.py](https://github.com/Kadsoo/AI-infra-project/blob/4f4c600367b02b82b389689b9a7ece2b2af4c4b9/tasks/continuum/cloud_repro/run_relaxed.py)，未运行 GPU wrapper。

- wrapper 在内存中替换 gpu_process_scope，记录邻居 PID 后返回 own 与 foreign 的并集，以及空的 foreign 集合。磁盘源码不变，但运行时检查行为改变。
- 因此它运行期间的 resources.json 中 foreign_gpu_pids 会被清空。REPRO.md 最后一条建议只看该字段，不能用于这个 wrapper；应检查 FOREIGN_LOG 的 t 时间戳是否与 summary.json 的 start_wall_time/end_wall_time 重叠。
- FOREIGN_LOG 默认是 /tmp/foreign.log，不是自动按轮次创建的文件；每次应显式指定不同的绝对路径，并保存到实验结果中。
- 当前 run.py 启动前还直接检查显存、利用率和 compute_apps，这部分没有被 wrapper 覆盖。因此它不保证能在启动时已有邻居进程的情况下运行。
- RELAX_ABLATION=1 还会跳过 verify_checkout；标准复跑保持该开关未设置。共享卡模式与绕过发布校验是两件不同的事。
- 共享 GPU 有重叠干扰的结果应单独标记；即使未记录到邻居，也不能排除采样间隔内的短任务干扰。正式性能比较优先使用独占时段。
