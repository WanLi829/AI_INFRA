# 单卡 RTX 4090D 24 GB 工作负载先导结果

**建议组内先采用 Qwen3-8B BF16、SWE 多轮回放子集 `pilot_14`、0.1 个程序/秒作为功能基线。** 在杨智涵完成的一轮 GPU 回放中，14 个程序、161 次模型调用全部完成。万理复核了逐程序和逐请求日志。目前的证据足以选定一个可重放的起点，最佳压力和稳定容量仍待多档实测。

## 负载如何定义

固定 14 个程序及其次序，保留每个程序的多轮调用及轮间等待。程序按泊松过程到达，随机种子为 20261030。0.1 JPS 表示平均每 10 秒到达一个新程序，每个程序会产生多次模型调用。服务端配置为单张 RTX 4090D、30 GiB 容器内存、8 个生成槽位、8 GiB CPU KV 缓存容量、16K 长度上限。

## 已有 GPU 实测及本轮复核

| 指标 | 0.1 JPS 单次结果 |
|---|---:|
| 程序完成数 | 14 / 14 |
| 调用完成数 | 161 / 161，失败 0，未发起 0 |
| 实际输出 | 24,182 token，逐请求均达到计划输出长度 |
| 同时在途的程序数峰值 / 请求数峰值 | 7 / 7 |
| 程序完成耗时（含排队及工具等待） | 中位数 50.87 秒，P95 为 69.77 秒 |
| 请求首 token 延迟 / 端到端延迟（P95） | 0.47 秒 / 9.54 秒 |
| 全程输出吞吐 | 136.68 token/秒 |
| 采样显存峰值 | 22,666 / 24,564 MiB，约 92.3% |

在途峰值由开始与结束时间的重叠数计算。吞吐按首个程序实际到达到回放结束的 176.92 秒计算，包含等待与最后一批请求的收尾。程序耗时的 P95 仅来自 14 个程序。运行时对无法归属的 GPU 进程仅作记录，因此显存为整卡采样值，不能据此推算模型独占显存或增加并发后的余量。

## 选型结论与待验证项

0.1 JPS 已覆盖多程序重叠，也有一份可逐请求核查的完整记录，可作为下一轮调度对比的共同起点。当前没有相同样本在 0.05 和 0.2 JPS 的 GPU 对照，也没有 0.1 JPS 的独立重复。三档输入已按同一随机种子生成，0.1 JPS 输入与原始文件逐字节一致。待目标实例可用后，固定模型、程序、轮间等待及服务配置，测两端压力并复跑基线，再根据完成率、尾延迟、吞吐和显存决定正式压力档位。

**数据来源**　杨智涵《B_数据分析与Replay准备》交付包，`verification/pilot_14/b_replay/` 下的 `jobs.json`、`requests.jsonl` 和 `summary.json`，以及随包 GPU 配置与资源监测记录。本轮工作为原始记录复核和三档输入校验，新增 GPU 运行次数为 0。
