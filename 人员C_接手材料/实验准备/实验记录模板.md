# 单次实验记录模板

每次实验复制一份并以唯一 run ID 命名。模板没有实验结果；“待填”不是 0。建议 run ID：`日期_操作者_方法_负载版本_r01`，已有目录不覆盖。

## 2. 实际执行命令

粘贴本次实际命令、必要环境变量、运行工作目录；去除密码、令牌等凭据。保留完整标准输出与标准错误。不要只记录“参考 REPRO”。

待填。

## 3. 完整性验收

- [ ] 运行前源码、负载、模型校验通过，保存输出。
- [ ] state.json 显示 complete，程序退出码为 0。
- [ ] `(program, turn)` 集合与输入预期一致，没有缺失、额外或重复请求。
- [ ] 每个请求 error 为空，实际输出 token 数等于计划预算。
- [ ] 所有程序完成；未出现 OOM、超时、资源守护中止。
- [ ] 已检查 GPU 共享干扰；若存在，明确标为探索结果。
- [ ] 已保存整个 run 目录及环境、配置、校验材料。

失败时保留首次错误、失败阶段、已完成请求数和复现步骤。未生成 summary.json 不等于没有失败证据。

## 4. 指标与口径

| 指标 | 本次值 | 来源和解释 |
|---|---|---|
| 成功请求 / 失败 / 完成程序 | 待填 | summary 与逐请求、逐程序日志交叉核对 |
| TTFT 均值 / P95，秒 | 待填 | summary 的 ttft_*；从请求提交到首个带 token ID 的流块，块内多 token 时并非精确单 token 到达时间 |
| 请求 E2E 均值 / P95，秒 | 待填 | e2e_*；从请求提交到流结束 |
| 程序 JCT 均值 / P95，秒 | 待填 | jct_*；含程序内工具等待，不含到达前等待和程序前的人类等待 |
| 请求吞吐，次/秒 | 待填 | request_throughput；分母 wall_s 是整段回放时间，包含到达与工具等待 |
| 输出吞吐，tokens/秒 | 待填 | output_token_throughput；来自实际输出 token IDs，不能用流块数量代替 |
| 回放 wall_s / 全流程耗时 | 待填 | 两者分开；加载、编译、预热不在回放 wall_s 内 |
| ITL 与样本覆盖 | 待填 | 当前 itl_* 只采相邻两个均为单 token 流块的间隔；缺样本时不做全量 ITL 结论 |
| GPU 显存峰值，MiB | 待填 | 注明采样来源、频率、运行窗口及设备/进程口径；采样峰值可能漏掉瞬时尖峰 |
| CPU 内存 / helper RSS 峰值 | 待填 | 注明容器总量还是具体进程，不能混用 |
| 缓存命中与传输量 | 待填或未采集 | 记录实际服务端计数器名称、单位、测量前后差值；不同策略先确认口径一致 |

不得将 `source_cached_tokens` 当作本次缓存命中；不得将前缀保留比例当作命中率。total_token_throughput 统计提交的输入加输出，不代表 GPU 实际计算量。
