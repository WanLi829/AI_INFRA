# 万理的 Replay 离线检查工具

完成日期：2026-11-02。只需要本地 Python 标准库，不需要服务器、显卡或安装第三方依赖。

## 能做什么

检查面向 Kairos `7971fa4` 接口的候选负载，并输出中文报告与 JSON 明细：

- JSON 能否读取、是否存在重复键或非有限数值。
- 程序 ID 是否重复，前驱是否存在，依赖是否有环。
- 当前回放器直接读取的程序/轮次字段是否齐全。
- token ID、输出预算和前缀长度是否合法；逐轮重建输入并核对声明长度。
- 可选检查“输入 + 输出预算”的上下文上限、token ID 的词表上界。
- 消息的程序集合、轮数、角色和基础结构是否匹配。
- 协议中的消息文件哈希、逐请求 token 签名、签名覆盖范围和重复签名。
- 对共享 cache_salt、未知来源元数据、被忽略的末轮等待等给出提醒。

通过不代表模型能跑、显存够用或已满足发布校验；工具也无法通过字符串结构证明消息没有未来信息。tokenizer、chat template、数据语义和来源仍需另行核查。

完整归档的两个警告：

1. **协议来源哈希不一致。** `visible_protocol.json` 的 `trace_sha256` 是 `ea7dc28e…`，当前 trace 原始文件哈希是 `4c896b93…`。上游 `verify_workload` 只校验消息哈希和逐请求签名，不检查这一字段，因此本工具单列警告；不将其擅自判为数据篡改，也不自动“修复”。需要维护者解释来源记录。逐请求签名全部匹配也不能证明到达时间、工具等待等非 token 字段没有变化。
2. **词表上界未核对。** 本次未提供实际 tokenizer 的词表范围，只验证 token 是非负整数。不能从模型参数规模猜测词表大小。

本次上下文上限使用固定版本的 16,384；这不是未来所有模型的通用默认值。

## 收到新数据后怎样用

打开 PowerShell，进入当前项目根目录：

```powershell
Set-Location 'C:\Users\USER\Desktop\学习\大三上\大模型网络'
```

完整材料应包含三个配套文件：`trace.json`、`visible_messages.json`、`visible_protocol.json`。下面的输入路径是占位示例，替换为实际收到的路径；输出目录每次使用新名字。

```powershell
python -B -X utf8 '人员C_接手材料/Replay检查工具/check_replay.py' --trace '收到的数据/trace.json' --messages '收到的数据/visible_messages.json' --protocol '收到的数据/visible_protocol.json' --output '人员C_接手材料/Replay检查工具/验证结果/新负载_01'
```

已确认运行配置后，可在命令末尾添加 `--max-context 16384`；只有确认实际 tokenizer 的 token ID 上界后，才添加 `--vocab-size 数值`。没有提供的检查项会明确标为未执行，不会猜测模型配置。

若只有 trace，保留 `--trace` 与 `--output` 即可，工具将做部分检查。不要把 `signatures.reference.json` 样例数组当成完整 `visible_protocol.json`。

检查完成后打开输出目录中的 `检查报告.md`：先处理 error，再逐项解释 warning。不要为了通过而随意补 0、统一 cache_salt 或重签协议。

## 可直接复查已有完整归档

以下输入已保存在本项目中，不依赖临时仓库目录。`复查_01` 不存在时可直接运行：

```powershell
python -B -X utf8 '人员C_接手材料/Replay检查工具/check_replay.py' --trace '人员C_接手材料/实验准备/负载分析/source/trace.json' --messages '人员C_接手材料/实验准备/负载分析/source/visible_messages.json' --protocol '人员C_接手材料/实验准备/负载分析/source/visible_protocol.json' --max-context 16384 --output '人员C_接手材料/Replay检查工具/验证结果/复查_01'
```

工具不修改输入，不执行对话中的命令，不导入 Kairos，不访问网络，不生成替代签名。输出目录已存在时拒绝覆盖。

## 退出码

| 退出码 | 含义 |
|---|---|
| 0 | 提供了三个文件，已完成支持的结构/签名检查且无错误；仍须阅读警告及边界 |
| 1 | 检查发现错误，报告中有位置和原因 |
| 2 | 命令参数错误，或输出目录已经存在 |
| 3 | 已提供材料未发现错误，但消息或协议缺失，仅做了部分检查 |

`source_gap_s`、`source_cached_tokens`、`source_tool_failures` 允许显式 null 并给出警告，因为当前客户端只记录这些字段；不建议新数据在不知道真实值时伪造数值。程序等待时间不能为 null，因为回放实际使用它。
