# 可整合进最终报告的文献依据与选型说明

作者分工：董悦君（A）｜资料截至 2026-10-30｜以下正文不包含尚未开展的 GPU 实验结果

## 文献依据

本项目研究交替执行 LLM 推理与工具调用的多轮 Agent 工作负载。Continuum 指出，工具等待不仅带来 KV cache 的重算或重载，还会使续轮重新排队，因而需要同时考察缓存驻留和程序级调度。该方法用有限 TTL 保留 GPU KV，并结合 program-level FCFS。本研究据此保留程序内部的调用依赖和工具反馈间隔，以程序完成时间为主要指标。[1]

Autellix 从程序级等待和依赖出发研究 Agent serving，说明孤立请求的延迟不足以评价完整程序。[2] InferCept 研究外部交互中断期间的保留、交换和丢弃选择，说明不同工具耗时可能改变缓存管理的收益。[3] 因此，本项目在 JCT 之外记录请求延迟、缓存传输和资源使用，并区分原始工具反馈时间与人工构造的等待。

## 工作负载选择

A 侧推荐主负载为 SWE-bench Verified 上的公开 mini-swe-agent teacher 轨迹，备选为 BFCL v4 Web Search。主数据固定到 Hugging Face revision `58389eb5426db5a3ae6159faa37498072b4735ff`，来源模型为 Qwen3-30B-A3B-Instruct-2507。[4] 该数据可提供有序对话、工具反馈、输出 usage 和时间戳，适合构建保持多轮结构的 serving replay。备选 Web Search 与编码 Agent 的工具类别不同，可用于扩展场景，但已核查的官方题目文件不含完整执行轨迹与工具耗时，须补齐后才能纳入实验。[5]

本次先对 Kairos 已有的 16 个 program ID 及对应原始轨迹做来源核查。原始状态中 14 条为 Submitted，2 条为 LimitsExceeded；前者共 161 次调用，推荐作为首轮小规模完整轨迹候选。Submitted 仅表示提交结束，不表示 SWE-bench 任务正确。该批 ID 来自已有开发材料，不作为独立盲测证据。正式扩展需按 program ID 检查训练、调优与测试的交集，并披露过滤规则。

逐轮时间对照发现，Kairos 现有压力输入改写了全部 16 条程序的首个工具间隔，162 个间隔的均值由原始的 0.3568 秒变为 0.5626 秒。这类 burst 输入保留作机制压力对照；主实验建议保留原始可观测反馈间隔，并独立生成固定种子的 Poisson program 到达。续轮只有在前一轮实际完成并经过相应工具等待后才能提交。

## 单卡适配与复现范围

目标设备为单张 RTX 4090 24GB。模型候选采用 Qwen3-4B/8B BF16，实际模型与资源配置须经实现支持检查和试跑确定。两者官方配置均为 36 层、8 KV heads、head_dim 128，在 BF16 下每 token 的原始 KV 都是 144KiB。[6][7] 因此，缩小权重规模不意味着按相同比例缩小 KV cache；GPU KV 页数、CPU KV 上限和到达率需按目标机器的实际容量和延迟标定。

本项目与 Continuum 原论文存在模型、GPU、teacher 轨迹和引擎版本差异。作者公开仓库又明确说明 preview 不含论文估计模块；Kairos 内部 Continuum 路径属于兼容实现。[8][9] 因此，后续结果应描述为在受限单卡环境中的适配与负载实验，不能宣称逐点重现原论文性能。固定 teacher 输入和输出预算的 replay 评价 serving 行为，不验证自主工具决策或任务解决率。最终选型和配置应在 B 完成格式核验、C 完成端到端试跑后共同冻结。
