# 文献调研与 4090 24GB 负载选型报告

董悦君（A）｜v1.0｜2026-10-30

## 1. 选型结论

**主负载：SWE-bench Verified 上的公开 mini-swe-agent teacher 轨迹。备选：BFCL v4 Web Search。** 优先保证多轮依赖、历史前缀、逐轮输出预算、工具反馈和等待区间可核验，再增加数据规模。

主负载的具体入口为 [tarsur385 的公开数据集](https://huggingface.co/datasets/tarsur385/qwen3-30b-a3b-instruct-2507-swebench-verified-mini-swe-agent/tree/58389eb5426db5a3ae6159faa37498072b4735ff)，固定 revision `58389eb5426db5a3ae6159faa37498072b4735ff`。它包含 Qwen3-30B-A3B-Instruct-2507 生成的 mini-swe-agent 对话，**不是 Continuum 作者的 GPT-5 原始实验轨迹**。本次已取得与 Kairos 16 个 ID 对应的原始 JSON；只把其中 14 条 Submitted 作为第一批完整轨迹候选。

备选采用 [BFCL 官方 Web Search 题目](https://github.com/ShishirPatil/gorilla/blob/6ea57973c7a6097fd7c5915698c54c17c5b1b6c8/berkeley-function-call-leaderboard/bfcl_eval/data/BFCL_v4_web_search.json)。本次下载文件有 100 行 JSON；其字段是 `id/question/involved_classes`，并非 100 条带时间的完整运行轨迹。必须先取得或采集逐轮消息、输出与工具耗时，才能进入正式回放。

这是一份证据支持的 A 侧建议；与 B、C 的共同选择和硬件可行性仍需实际验收。

## 2. Continuum：论文方法与实验设置

### 2.1 版本和方法定位

准确入口：[arXiv:2511.02230](https://arxiv.org/abs/2511.02230)。截至核查日，最新版本为 **v7，2026-09-08**；本报告以 [v7 全文](https://arxiv.org/html/2511.02230v7) 为主。旧版 v3 和 ICLR Workshop 版可供对照，不应把不同版本的模型或实验结论拼在一起。v7 HTML 正文存在 “Continnum” 拼写，本文统一称 Continuum，并以 arXiv ID 固定身份。

方法的核心是：在工具执行期间为 GPU KV 设置有限 TTL，并结合 program-level FCFS，兼顾重建缓存代价、续轮排队和工具耗时不确定性。它不只是降低一次 prefill，也试图维持整个多轮程序的连续推进。[论文 §3–§5](https://arxiv.org/html/2511.02230v7#S3)

### 2.2 资源、数据和到达方式

| 项目 | 论文明确说明【论文】 | 本次采用方式【建议】 |
|---|---|---|
| 推理模型 | §6.1 列出 Llama-3.1 8B/70B、Gemma-3 12B；另有 OpenHands/GLM 扩展实验 | 4B 试通、8B 复核；与论文模型不同须单列 |
| 硬件 | A100-SXM、H100、B200；图示包含 8B 单卡 A100 设置 | 单张 RTX 4090 24GB，不外推原硬件加速比 |
| 基础引擎 | vLLM 0.10.2，chunk size 2048 | 由实现小组提交决定，记录精确版本 |
| CPU KV | LMCache 0.3.7；A100 为 100GB；B200/H100 为每 GPU 200GB | 先按可用 RAM 与 KV 压力选 4/8GiB 探索点，不能直接照搬 |
| 轨迹来源 | §3.1：100 条 SWE/mini-swe-agent 和 100 条 BFCL v4 Web Search，使用 GPT-5 | 用公开 Qwen teacher 数据替代，注明采集模型变化 |
| 到达 | program 层面的 Poisson 到达 | program 首次到达由固定种子产生；续轮保持依赖 |
| 上下文控制 | SWE 保留在上下文窗口内的请求；BFCL 描述了 0.4 缩放 | 暂不复刻 0.4；其具体缩放对象、边界规则未由已读公开代码确认 |
| 回放与真实执行 | 有 trace replay，也有真实 SWE-agent 分布式实验 | 第一阶段做固定轨迹 serving replay；不报告 agent 正确率 |

来源：[论文 §3.1、§6.1–§6.3](https://arxiv.org/html/2511.02230v7#S6)。本表明确保留未确认项；论文提到的 BFCL 0.4 不能自行解释成工具时间或 CPU 内存乘 0.4。

论文表 2 的轮数（SWE 10.9±2.1、BFCL 6.3±2.3）和工具时间（925ms、1923ms 的均值）仅作描述参考。其 “Token Per Program” 不应直接当作单请求上下文长度或瞬时显存需求；本项目应同时统计逐请求 token、最终上下文及各轮重复输入总量。[论文 §3.1](https://arxiv.org/html/2511.02230v7#S3.SS1)

### 2.3 作者代码能确认什么

作者仓库：[Hanchenli/vllm-continuum](https://github.com/Hanchenli/vllm-continuum)，本次固定提交 `316a58794a6ff86b216e579b74fd56ed0c5a911f`，提交时间 2026-03-20。

其 [README](https://github.com/Hanchenli/vllm-continuum/blob/316a58794a6ff86b216e579b74fd56ed0c5a911f/README.md) 明确说明公开版本不含论文估计模块。仓库提供 `--scheduling-policy continuum`、LMCache CPU KV 参数、固定并发与 Poisson JPS 两种 mini-swe-agent 运行方式。默认示例是 70B / 4×H100，而非 4090。说明与论文 v7 之间存在版本差距。

实际读取的 [客户端](https://github.com/Hanchenli/vllm-continuum/blob/316a58794a6ff86b216e579b74fd56ed0c5a911f/mini-swe-agent/src/minisweagent/models/vllm_model.py) 使用 `chat.completions`，带 `job_id/is_last_step`。Kairos 归档则采用固定 teacher 输入及其自定义运行接口，不能把这两个客户端当作可直接互换。

在所检查提交的完整文件清单中，没有发现可明确识别为论文两组 GPT-5 完整计时轨迹的发布文件。仓库提供运行入口和结果文件，不足以证明原始 trace 已完整公开；这不等于证明作者从未在其他位置发布。论文 §9 链接该仓库，仍需按实际文件核验。

## 3. 相关文献：两篇系统论文

### 3.1 Autellix

[Autellix: An Efficient Serving Engine for LLM Agents as General Programs](https://arxiv.org/html/2502.13965v1)，arXiv:2502.13965v1（2025）。本报告固定 v1，未假定它是最新修订。

论文以程序为调度单位，提出 PLAS/ATLAS，帮助解释为什么单请求 TTFT 无法代表整个 Agent 的完成时间。其工作负载覆盖 ShareGPT 完整会话、BFCL **v3**、LATS 和混合程序；按程序抽样并生成 Poisson 到达。8B/70B/Falcon-180B 分别用 1/4/8 张 A100，基于 vLLM 0.6.1。主要延迟口径包含程序响应时间按生成 token 归一化，不能直接等同本文的未归一化 JCT。[§5–§6](https://arxiv.org/html/2502.13965v1#S6)

对本项目的作用：支持保留程序依赖、整程序采样，以及同时报告程序和请求级指标。BFCL v3 与 Continuum 的 v4 Web Search 是不同实验对象，不能混用两篇论文的轮数统计。LATS 的树形并行依赖会增加当前回放接口的适配负担，因此不作为首轮主负载。本次未核实 Autellix 的作者代码入口，不以猜测链接作为已验证交付。

### 3.2 InferCept

[InferCept: Efficient Intercept Support for Augmented Large Language Model Inference](https://arxiv.org/html/2402.01869v2)，arXiv:2402.01869v2 / ICML 2024；[作者代码](https://github.com/WukLab/InferCept)。

论文在工具暂停时权衡 preserve、swap、discard，并研究交换/重算分块。评估包括 Math、QA、ALFWorld 虚拟环境、Chatbot、Image、TTS 六类增强；其中有实测和估计的人类/外部交互时间。模型为 GPT-J-6B、Vicuna-13B、Llama3-70B，对应单卡或多卡 A100。论文的归一化请求延迟**扣除了 interception 时间**，不能直接与包含工具等待的 program JCT 比较。[§2、§4、§5](https://arxiv.org/html/2402.01869v2#S5)

对本项目的作用：提供短等待与长等待场景设计依据，并要求所有工具时间标明“原始观测/采集/合成”。其混合增强不天然等价于现代多轮编码 Agent；首轮不额外引入图像/TTS 模型，以免把工具计算资源变化混入 KV 策略测试。公开仓库 README 指向 `exps`，但本次未逐一运行其数据生成与实验脚本。

## 4. 候选比较和推荐理由

| 候选 | 文献关联 | 已验证可取得内容 | 主要缺项 | 定位 |
|---|---|---|---|---|
| 公开 SWE / mini-swe-agent teacher | 与 Continuum 的 SWE 负载同类 | 固定 revision、16 条原始对话、输出 usage、反馈时间戳 | 最终 tokenizer、全数据集筛选、独立测试划分 | **主负载** |
| BFCL v4 Web Search | 对应 Continuum 的第二类负载 | 100 条题目、WebSearchAPI 定义 | 完整逐轮 trace、原始工具耗时、输出预算 | **备选，有条件启用** |
| Kairos 现有 burst replay | 相同项目接口、已有历史 4090 记录 | 16 programs / 178 calls、增量 token IDs、现成配置 | 到达与首轮 gap 人为改写，2 条源轨迹不完整 | 接口试跑/压力对照 |
| BFCL multi_turn_base | Autellix v3 多轮选型的参考方向；当前下载为 v4 文件 | 题目和任务结构 | 不能由题目直接得到实际 LLM 调用数与工具时间 | Web Search 获取轨迹受阻时再评估 |
| LATS / 混合增强 | Autellix / InferCept | 有论文与项目入口 | DAG/额外模型/交互假设提高适配成本 | 后续扩展，不纳入首轮 |

选择主负载的理由是当前来源最可核查，具有真实多轮前缀和观测到的工具返回时间，且与 Kairos 现有输入能逐轮对齐。选择 Web Search 作备选，是为了覆盖不同工具耗时和上下文结构，而非仅扩大同一类 SWE 样本。BFCL 是否真正可用，取决于 B 能否补全 trace；题目 JSON 本身不能通过回放验收。

## 5. 本次实查结果及对选型的影响

### 5.1 已核查的数据范围

核查范围为 Kairos 固定提交中已有的 16 个 ID，以及对应的 16 个原始 teacher 文件，**不是 499 条原始轨迹的随机样本**。重算脚本为 [scripts/audit_sources.py](scripts/audit_sources.py)，完整输出在 [audit/source_audit.json](audit/source_audit.json)。

| 项目 | 本次重算 |
|---|---:|
| 程序/调用 | 16 / 178 |
| 每请求 prompt tokens | 1218–11455，均值 5144.01 |
| 每请求输出预算 | 39–699，均值 146.99 |
| 最终输入上下文 | 6056–11455，均值 8003.56 |
| 最大 prompt + output | 11717 tokens |
| 非终止工具间隔 | 162 个 |
| 原始反馈间隔 | 均值 0.3568s，P95 1.3160s，最大 6.4765s |
| Kairos 发布回放间隔 | 均值 0.5626s，P95 2.9772s，最大 6.4765s |
| 被改写的间隔 | 16 个，全部是各程序首轮 |
| 声明可保留的输入前缀比例 | 786928 / 915633 = 85.94% |
| 原始退出状态 | Submitted 14 条；LimitsExceeded 2 条 |

前缀比例来自 `keep_prefix_tokens` 与输入总量，不是 GPU cache hit rate。178 个输入按 `previous_prompt[:keep] + added_token_ids` 重建，其长度与声明值一致；这只验证结构，不替代 tokenizer 验证或实际输出的前缀复用。

### 5.2 必须纠正的完成性描述

原始文件 [astropy__astropy-13453](https://huggingface.co/datasets/tarsur385/qwen3-30b-a3b-instruct-2507-swebench-verified-mini-swe-agent/blob/58389eb5426db5a3ae6159faa37498072b4735ff/trajectories/astropy__astropy-13453.traj.json) 与 [django__django-16256](https://huggingface.co/datasets/tarsur385/qwen3-30b-a3b-instruct-2507-swebench-verified-mini-swe-agent/blob/58389eb5426db5a3ae6159faa37498072b4735ff/trajectories/django__django-16256.traj.json) 标记 `LimitsExceeded`。这与 Kairos EXPERIMENTS 中“完整、自然结束”的描述存在差异。文件本身仍可做有限轨迹压力回放，但必须标明停止原因，不能当作自然任务结束。

建议首轮用 14 条 Submitted（161 calls）供 B 做完整轨迹试跑；不得把 Submitted 解释成 SWE-bench resolved。这个小批来自既有开发 ID，不能用于证明未知数据上的泛化。正式测试需要 B 在全数据源中按预先固定规则筛选，并按 program ID 排除训练/调优重合。

### 5.3 到达和等待时间

Kairos 的 `frontier` 明确说明按 program ID 构造两组到达，并回推首轮工具等待来靠近某个返回窗口。逐条比较原始 assistant 完成时间与后续最后一条 tool 反馈时间，确认首轮改写。因此 `source_gap_s` 字段也不能作为原始工具时间的可靠替代。

主负载保留可观测原始反馈间隔；它包括工具、沙箱和客户端反馈开销，不能称纯工具 kernel 时间。到达记录没有自然生产流量意义，应另用固定种子 Poisson 生成。burst 只作为单独的压力对照，不纳入“自然到达”的主结论。

## 6. 4090 适配的证据和边界

官方 [Qwen3-4B 配置](https://huggingface.co/Qwen/Qwen3-4B/blob/1cfa9a7208912126459214e8b04321603b3df60c/config.json) 和 [Qwen3-8B 配置](https://huggingface.co/Qwen/Qwen3-8B/blob/b968826d9c46dd6066d109eabc6255188de91218/config.json) 都是 36 layers、8 KV heads、head_dim 128。在 BF16、完整 attention KV、TP=1 下：

`KV bytes/token = 2 × layers × KV_heads × head_dim × 2 = 147456 = 144 KiB`。

所以两者单序列 8192 tokens 的原始 KV 均为 1.125GiB，16384 tokens 均为 2.25GiB。**从 8B 换到 4B 会减轻权重压力，但该模型对的每 token KV 并不会减半。** 页取整、运行 workspace、图捕获和共享前缀还会影响真实分配，不能用 24GB 减权重直接算最终并发数。

建议 4B 优先验证接口；实现已支持 8B 且显存允许时再做 8B 复核。默认先不引入权重/KV 量化，以免混入新的数值与恢复差异。GPU KV 容量、CPU KV 容量和 Poisson JPS 都应由 C 的 profile 与试跑确定；CPU 核数、CPU 总 RAM、CPU KV cache 是三个不同参数，不按模型参数量统一同比缩小。
