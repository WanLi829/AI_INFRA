2026-11-05。已实现五方法计划/启动入口和统一汇总，本地配置、模拟协议及错误处理验证通过。GPU 引擎加载、LMCache 连接及实际性能仍待目标卡验证。

采用独立的 comparison-v1-cold-process 流程。每次新启动引擎及所需 helper，等待引擎初始化、图捕获和健康检查完成后直接回放。所有方法均不发送额外客户端预热或布局测试请求，以获得一致的缓存初始状态。旧先导采用了额外预热与布局测试，比较程序会拒绝混用其结果。

## 本地查看配置

进入本交付的 project 目录，用 Python 运行下面的命令。计划检查只读固定输入及配置，不加载 GPU。

```bash
python -X utf8 -B -m b_replay.comparison plan \
  --method native \
  --bundle bundles/Qwen3-8B/pilot_14 \
  --arrivals arrivals/pilot_14_jps0.1_seed20261030.json \
  --model /models/models--Qwen--Qwen3-8B/snapshots/b968826d9c46dd6066d109eabc6255188de91218 \
  --output runs/native01
```

方法可选 native、lmcache、static_ttl、continuum、kairos。static_ttl 必须显式增加 --ttl-seconds 2；该常数是预登记的工程消融值。此版本尚未实现论文冷启动估计生成的静态阈值，因此结果应标为“固定 TTL 2 秒工程对照”。其他方法拒绝 TTL 参数。

原生方法保留标准请求调度和 prefix caching。LMCache 方法使用标准 LMCacheConnectorV1 和 8 GiB CPU 缓存。两者均不加载自定义 worker 或 scheduler。static_ttl 在 Continuum 的同一调度类上设置固定 TTL，并验证策略切换后仍保持 fixed；上卡完成时还要求日志出现实际 pin 事件，且事件阈值与传入常数一致。

## 在服务器上运行

把本版 project 放到个人数据盘工作区，与已核对的私有 env 目录相邻。入口使用 project 中的新客户端与适配代码，冻结的 Kairos 核心文件由原始清单校验。若沿用旧工作区，应先把本版放进单独目录并配置相邻环境，避免覆盖他人的项目。

先核对 GPU 空闲、Python 3.12、vLLM 0.28.0、固定 snapshot 及环境锁。所有启动均使用 strict 检查、独立进程组和内存/OOM 监测。以下命令从 project 目录执行，MODEL 与 OUT 替换为现场实际路径。

```bash
../env/bin/python scripts/gpu_python.py -m b_replay.comparison run \
  --method native \
  --bundle bundles/Qwen3-8B/pilot_14 \
  --arrivals arrivals/pilot_14_jps0.1_seed20261030.json \
  --model "$MODEL" --output "$OUT/native01"
```

更换方法和对应到达表即生成各实验组合。输出目录必须新建，路径应较短以容纳 Unix socket。先用 pilot_1 做逐方法接口检查，使用以下命令生成相应输入，再将启动命令的 bundle 和 arrivals 改为这个小样本。

```bash
python -m b_replay arrivals --bundle bundles/Qwen3-8B/pilot_1 \
  --jps 0.1 --seed 20261030 --output runs/pilot1_arrivals.json
```

正式比较继续用 pilot_14。每轮结束保存整个输出目录，并检查方法配置、实际 KV 块数（服务日志）、GPU 资源样本、接口完整性和缓存传输指标（若服务输出）。LMCache 在固定环境中的标准 connector 兼容性需由第一次 GPU 小样本验证。若失败，先保留日志并修复该入口，随后再进入正式矩阵。

默认启动超时 1200 秒、回放超时 900 秒、单请求超时 120 秒，可通过命令行设置。每轮计时范围仅覆盖回放；平台费用包含启动等全过程。当前总授权 4 元，执行前按实际剩余预算判断是否能启动下一轮，结束后下载日志并关闭实例。

## 汇总

```bash
python -X utf8 -B -m b_replay.comparison_results \
  --bundle bundles/Qwen3-8B/pilot_14 \
  --run "$OUT/native01" --run "$OUT/kairos01" \
  --output comparison01.json
```

可多次追加 --run，收集五种方法、多个到达率和重复轮次。程序逐请求核对签名、输出数量、唯一身份及等待顺序，从程序时间复算平均 JCT。失败运行保留完成数与错误；没有同条件原生运行的分组，加速比为 null。少于三次的结果标为探索性。比较键包含输入、到达表、模型路径、GPU UUID、软件版本、适配代码及主要引擎参数。固定 TTL 的不同常数分别分组。

## 本地验证记录

- 三档、五方法共 15 个计划通过，冻结核心 179 个文件均通过原始校验。
- 五个客户端均用真实 pilot_14 数据完成 14/14 程序、161/161 调用；模拟服务检查完整整数 prompt、输出预算及方法专属字段。
- HTTP 失败检查保存 1 次失败、9 次未发送请求。
- 固定 TTL 策略切换回归检查通过。该检查模拟 GPU 父类的策略重置，实际引擎行为由上卡日志验收。
- 汇总计算测试确认 60/40 得到 1.5，并拒绝为没有匹配原生的分组填写收益。

本地验证未产生 GPU 性能数据。完整测试入口为 python -B -X utf8 -m unittest tests.test_comparison -v。[本地验收日志](多方法本地验收.log)

实现接口依据为固定 vLLM 0.28.0 的 CompletionRequest 中整数输入、return_token_ids 和 cache_salt 字段，以及 LMCache 官方 CPU connector 配置。[vLLM 协议](https://github.com/vllm-project/vllm/blob/v0.28.0/vllm/entrypoints/openai/completion/protocol.py) · [LMCache CPU 配置](https://docs.lmcache.ai/kv_cache/storage_backends/cpu_ram.html)
