# 如何复跑这套负载

2026-11-04 更新。本页命令用于原有 Kairos 先导回放。组长要求的五方法对比按[多基线对比方案](03_多基线对比方案.md)执行，新入口命令见[多方法运行说明](04_多方法运行说明.md)。

解压整个 ZIP 后进入包含 `replay.py` 的目录。下列命令都从该目录执行。交付针对已有的 Linux GPU 环境；模型权重和服务器环境保存在组内实例上。完整负载、到达表、选定的运行代码及先导原始日志已随包提供。

## 本地可复查

使用 Python 3.12 和 UTF-8 模式。下面两条命令分别检查启动计划和既有 GPU 日志。计划中的模型路径仅用于展示；这一步不会加载模型。输出目录名必须尚未使用。

```bash
python -X utf8 -B replay.py plan 0.1 --output runs/check01
python -X utf8 -B result_row.py project/verification/pilot_14
```

将 0.1 换成 0.05、0.2 即可检查另外两档。三份文件按冻结客户端重新生成后均逐字节相同；最后一个程序计划到达的时间依次为 243.22、121.61、60.81 秒（按低、中、高压力排列）。这些是输入时间，不含最后一个程序的执行与排空。[三档校验](离线启动核验.json)

另外，随包真实客户端已连接内存模拟引擎，完成小样本 10/10、44/44 次调用，以及主负载的 161/161 次调用。该检查使用快速到达表验证逐轮发送、可见消息与输出预算，结果只计入接口验收。[本地模拟回放记录](本地模拟回放.json)

## GPU 可用之后

1. 将完整交付包放在数据盘自己的学号目录。确认原实例上 B 的隔离工作区、固定模型位置和可用时间，记录 GPU 型号/UUID、其他进程、容器内存限制、CPU 可用集合。B 的环境为 Linux x86_64、Python 3.12.4、torch 2.13.0+cu130、vLLM 0.28.0；项目旁须有配套的 `env/` 和私有 CUDA 编译器。本包的 GPU 依赖锁与[原环境记录](project/verification/gpu_environment.json)可用于比对。
2. 在同一终端设置以下三个变量，换成现场核对的绝对路径。输出目录选**自己的学号目录下的短路径**，以适应 Unix socket 长度限制。脚本会检查现有 B 项目的适配代码和冻结运行清单，并从本交付包读取输入。如果本人已有配套环境，也可将本包的 `project/` 放在该环境旁边作为 B_PROJECT。

```bash
export B_PROJECT="/实际路径/B隔离工作区/project"
export MODEL="/实际路径/snapshots/b968826d9c46dd6066d109eabc6255188de91218"
export OUT="/数据盘/本人学号/r"
mkdir -p "$OUT"
```

3. 先在服务器运行一次 `plan`，确认 14 个程序、161 个请求、Kairos、ram30、strict。再依次运行低压力、基线、高压力，每轮读取输出和核验状态后再进入下一轮。

```bash
python3 replay.py plan 0.05 --project "$B_PROJECT" --model "$MODEL" --output "$OUT/l1"
python3 replay.py run 0.05 --project "$B_PROJECT" --model "$MODEL" --output "$OUT/l1"
python3 result_row.py "$OUT/l1"

python3 replay.py run 0.1 --project "$B_PROJECT" --model "$MODEL" --output "$OUT/m1"
python3 result_row.py "$OUT/m1"

python3 replay.py run 0.2 --project "$B_PROJECT" --model "$MODEL" --output "$OUT/h1"
python3 result_row.py "$OUT/h1"
```

4. 每轮采用新的输出目录，默认 strict。若检测到其他 GPU 进程、OOM 或超时，保留该轮日志，并在结果表记录具体失败与已完成的请求数。历史先导使用 record-only，比较时应保留两者的进程检查差异。每轮启动和预热均计入平台使用时长，按**本轮预算 4 元**及现场费率留出关机时间。下载结果并确认实例关机。
5. 将每个成功轮次输出的表格行填入主报告。检查 `state.json`、`resources.json`、`b_input_provenance.json`、`gapped-correctness.json` 以及 `b_replay/` 中的 `summary.json`、`jobs.json`、`requests.jsonl`。对失败轮次保留原始目录及报错；缺少的指标记“未取得”。若新档位成为推荐档，用新目录重复验证。最后填入推荐理由与适用范围。
